# NOT added, and the reasons:
#   xgboost / lightgbm  — the sklearn ensembles already cover the tree rung of

#                         baseline here. A third boosting library would add
#                         install weight to a rung that is not the bottleneck.
#   shap                — permutation importance out-of-sample answers the same
#                         question without a heavyweight dependency, and
#                         split-gain importances are already surfaced with their
#                         caveat.
#   torch               — no result so far suggests the dataset supports a
#                         sequence model. Adding one before the linear rung is
#                         beaten would be adding capacity to fit noise.
#   duckdb / polars     — the local Dolt CLI aggregates 116M rows server-side and
#                         pandas handles what crosses the boundary. Neither is
#                         currently a bottleneck; see docs/quant/experiments.md.
