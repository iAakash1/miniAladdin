# EXP-008 — Can the evidence be made decidable at all?

**Status: PRE-REGISTERED. NOT IMPLEMENTED. NOT RUN.**

This document is written *before* the implementation exists, which is the point.
Everything below is a declared design. No result fields are filled, because
there are no results.

---

## 1. Why this experiment exists

EXP-007 searched 873 configurations and produced the best economics this project
has recorded: net Sharpe **+0.111** at the declared 10 bp, turnover 18.5×, seven
of ten gates passed. It still failed, and the three gates it failed all test the
same thing — whether the result is a selection artifact.

The bottleneck was measured, not guessed:

| | |
|---|---|
| effective independent blocks | 403 periods × 5 sessions ÷ 21-session label ≈ **96** |
| cumulative trials spent on them | **1,029** |
| **trials per independent block** | **10.7** |
| observed Sharpe ÷ search noise ceiling | 0.1106 ÷ 0.6439 = **0.17×** |
| PBO | **0.929** |
| minimum track record length | 10,545 periods required, **403** available |

**The search is roughly eleven times larger than the information content of the
sample.** More hyperparameter search cannot fix this and makes it worse: every
configuration raises the threshold, and the PBO shows selection is already
anti-predictive.

So EXP-008 does not search. It asks a different question:

> **Can this evidence base be made decidable — by increasing the number of
> independent observations and by fixing the return distribution that makes the
> required track record so long — without searching for a better model?**

## 2. The two hypotheses

Both are pre-declared. Both use a **frozen model specification** carried
unchanged from EXP-007's selected configuration. No hyperparameter is tuned.

### H1 — label overlap is destroying the effective sample

The panel rebalances every 5 sessions and labels 21 sessions forward, so
consecutive observations share 16 of 21 days of outcome. That is a 4.2×
overlap, and it is why 403 periods behave like ~96.

**Test:** add a `fwd_rank_5` label — a 5-session cross-sectional rank, matching
the rebalance step, therefore **non-overlapping** — and evaluate the frozen
specification against it.

**Why a rank and not `fwd_ret_5`, which already exists.** EXP-007's Stage 3
measured both target types across five feature arms and the result was
unambiguous:

| arm | `fwd_rank_21` | `fwd_ret_21` |
|---|---|---|
| A_price | +0.0143 | −0.0046 |
| C_base | +0.0332 | +0.0078 |
| D_base_options | +0.0305 | −0.0179 |
| E_base_estimates | +0.0295 | −0.0018 |
| G_all | +0.0096 | −0.0080 |

Rank targets are learnable on this panel and raw return targets are not. Using
`fwd_ret_5` because it happens to exist would be testing the horizon change and
the target-type change at once, and a negative result would be uninterpretable.

**Prediction, recorded now:** the IC will fall — a 5-session horizon carries
less signal than 21 — but the t-statistic may hold or improve, because the
effective sample rises ~4×. If the t-statistic *also* falls, the 21-session
horizon was carrying real information and the overlap was not the binding
constraint. Either outcome is informative.

**Cost:** this changes the label set, so it produces a **new dataset version and
content hash**. It is not comparable to EXP-004–007 fold-for-fold and will not
be presented as if it were.

### H2 — the return distribution, not the signal, is what makes this undecidable

The selected configuration's net return series has **skew 3.61 and excess
kurtosis 43.28**. Minimum track record length scales with those moments; they
are a large part of why 10,545 periods are required for a Sharpe of 0.0156 per
period.

The backtest builds a plain quantile book. This repository already contains a
portfolio layer (`quant/portfolio/optimizer.py`) and a risk engine
(`quant/risk/engine.py`) that the backtest **does not use**.

**Test:** apply four pre-declared allocators to the frozen signal, unchanged:

1. `equal_weight` — the current behaviour, as the control
2. `inverse_volatility`
3. `volatility_target`
4. `minimum_variance`

with position caps and the existing turnover constraint.

**Prediction, recorded now:** kurtosis falls and MTRL falls with it. Net Sharpe
probably falls too, because volatility scaling trades return for stability and
the signal is thin. If MTRL falls by less than an order of magnitude, this line
is closed: 10,545 → even 2,000 is still five times the sample.

## 3. Trial budget — declared before the run

| | |
|---|---|
| H1 configurations | 1 (frozen spec, one new target) |
| H2 configurations | 4 (pre-declared allocators) |
| **new trials** | **5** |
| prior | 1,029 |
| **cumulative** | **1,034** |
| expected max \|t\| under null | 3.38 → **3.39** |

Five trials, not five hundred. The bar moves by 0.01. **This is the entire
design philosophy of the experiment:** EXP-007 established that trials are the
scarce resource on this panel, so EXP-008 spends almost none.

Any deviation upward from five trials voids the pre-registration and requires a
new document.

## 4. Gates

The **ten-gate standard** registered 2026-09-01, unchanged and unmovable:
`ic_t_stat`, `gross_sharpe`, `net_sharpe`, `beats_best_baseline`, `not_overfit`,

the holdout are all inherited unchanged.

## 5. What would make us stop

Declared in advance, so that stopping is not a judgement call made while
disappointed:

- **H1 stops** if the t-statistic on the non-overlapping target is below +2.0.
  The horizon change would then have cost more signal than the sample gained.
- **H2 stops** if MTRL does not fall by at least an order of magnitude. A
  required track record of 1,000+ periods against 403 available is still
  undecidable, and a prettier distribution does not change that.
- **Both stop** if PBO stays above 0.5. Selection instability is the deepest of
  the three failures and the one least likely to be fixed by anything here.

If both stop, the honest conclusion is that **this dataset cannot support a
promotable model**, and the next question is about acquiring more independent
data — not about models, features, or compute.

## 6. Implementation required before this can run

Not yet built. Listed so the work is visible rather than implied:

1. A `fwd_rank_5` label in the label engine, with its own leakage test.
2. A backtest path that accepts an allocator from `quant/portfolio/optimizer.py`
   instead of the built-in quantile book.
3. An `EXP-008` definition in `study/experiment.py` with `search_budget=None`.

becomes a decision worth making — and it is a separate decision, made
